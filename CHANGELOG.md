## [1.0.0] — 2026-09-24

First public release. The pre-1.0 version was a personal macOS toolkit of six
numbered scripts; this is a rewrite.

### Added

- **Windows support.** A PowerShell module (`ClaudeProfiles`) covering both
  halves, plus the portable `claude-profiles <subcommand>` spelling so the
  docs read the same on every platform. Detects the two install flavours —
  direct `.exe` works immediately; MSIX / Microsoft Store cannot be launched
  with arguments at all and needs `New-ClaudeProfileMirror`. Windows
  PowerShell 5.1 and PowerShell 7+ are both supported and tested.
- **Linux support.** Both halves, with no workarounds needed: the desktop
  credential blob lives inside the user-data directory, so profiles cannot
  collide.
- **Any number of named profiles.** A registry at
  `~/.config/claude-profiles/profiles.json` replaces the single hardcoded
  `work` profile.
- **Per-directory switching.** A `.claude-profile` file switches the account
  on `cd`, via a native zsh/bash/PowerShell hook — no direnv required. The
  walk-up and name check happen in pure shell, so a directory without one
  launches no processes.
- **`doctor`**, with `--json` and an opt-in `--probe`. Absorbs and generalises
  the old `01-verify-desktop.sh`.
- **Per-profile MCP templates**, applied to each user-data directory on
  launch. `doctor` cross-references fixed ports across profiles and flags
  collisions, closing a documented failure that previously had no runtime
  symptom.
- **Prompt indicator** for PS1, starship, oh-my-posh and Claude Code's own
  `statusLine`.
- **One-line installers** for all three platforms. Neither edits your shell
  configuration.
- `doctor` finds each macOS profile's per-directory Keychain item (metadata
  only, never the secret) and suggests moving token profiles to config-dir.
- A redesigned terminal interface: status glyphs with an ASCII fallback, one
  accent colour, `~`-shortened paths, a table for `list`, and a pass/warn/fail
  tally at the end of `doctor`. `NO_COLOR` is honoured.
- The installers pin to the **latest release tag** by default, so a push to
  `main` never reaches people who installed a release.
  `CLAUDE_PROFILES_BRANCH` selects any tag or branch.
- A project website under `site/`, published to GitHub Pages.
- Two checks for footguns that previously had no coverage: `apiKeyHelper`
  (precedence rank 4) outranking a profile token, and `claude --bare`
  ignoring `CLAUDE_CODE_OAUTH_TOKEN` entirely — which silently runs a
  bare-mode script as your primary account.

### Changed

- **config-dir auth is the default on every platform, including macOS.**
  The pre-1.0 toolkit, and early 1.0 drafts, required
  `CLAUDE_CODE_OAUTH_TOKEN` on macOS because Claude Code kept every Mac login
  in one Keychain item. Current Claude Code names the item after the config
  directory (`Claude Code-credentials-<sha256(dir)[:8]>`), so
  `CLAUDE_CONFIG_DIR` isolates the login by itself. Profiles keep Remote
  Control and claude.ai connectors, and nothing expires after a year. Token
  auth remains available with `--auth oauth-token` for CI and older builds.
- The six numbered scripts became subcommands. `claude-profiles init` adopts
  an existing pre-1.0 setup in place — nothing moved, copied, or logged out,
  including the old Keychain token.
- Shell integration is generated by `claude-profiles shell-init` and contains
  no configuration, only the binary path and the profile names. The pre-1.0
  version hand-duplicated four constants into two files.
- `03-fallback-clone-app.sh` became `mirror-app`, now cross-platform and
  carrying the same explicit cost confirmation on both.
- Secret storage is abstracted over Keychain, DPAPI, libsecret and a
  mode-0600 file fallback — which announces itself rather than quietly
  downgrading.
- Token expiry now works on GNU coreutils. The pre-1.0 check used BSD
  `date -j -f` and failed silently on Linux.

### Removed

- `config.sh`, `01`–`05`, `99-uninstall.sh`, `shell/claude-profiles.sh`.
- `tests/smoke-test.sh`'s drift test. It policed four constants duplicated
  across three files; the registry means they exist once. It is replaced by
  `tests/registry-contract.sh`, which checks that the bash and PowerShell
  implementations serialise a registry byte-for-byte identically.

### Security

- `.claude-profile` is treated as untrusted input, because it arrives inside
  repositories you clone. It can only select an already-registered local
  profile by name; the character set is validated in pure shell before the
  name reaches any argv, and twice more after. An unrecognised name leaves you
  on the primary account and never falls through to a different profile.
- `doctor` never prints a secret, and its Keychain lookups omit `-w` so macOS
  reads metadata only and never prompts for authorisation during a
  health check.
- Destructive prompts decline on a closed stdin, so nothing is deleted under
  automation. `CLAUDE_PROFILES_ASSUME_YES=1` overrides — an environment
  variable rather than a flag, because a flag is too easy to copy out of a
  README.
- Registry is mode 600 and state directories 700; on Windows, ACLs are
  stripped to the current user with inheritance disabled.
