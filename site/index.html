Every project on the right Claude account.

Personal Pro and an employer's Team seat on one laptop? claude-profiles gives each account its own isolated profile, for Claude Code and the desktop app, and switches when you cd into a project. macOS, Linux and Windows.

$ curl -fsSL https://raw.githubusercontent.com/inevitable-lettus/claude-profiles/main/install.sh | sh

Installs the latest release into your home directory. Never edits your shell rc, never needs sudo. Read the script first.

The problem

Wrong account. Again.

Claude Code has one login per machine. If you have two accounts, you are one forgotten /logout away from putting client work on your personal plan.

  1. 01Log out, log in, repeat.Every context switch costs a browser round-trip, and the desktop app only holds one account at a time.
  2. 02History and settings bleed together.Sessions, MCP servers and project memory from one employer sit next to another's.
  3. 03Aliases are easy to forget.A claude-work alias works until the one time you type plain claude in the wrong repo.

How it works

Set it once per project. Stop thinking about it.

A small, readable bash and PowerShell tool built on Claude's own environment variables and one Electron flag. No daemon, no binary, no proxy.

Switches when you cd

Run claude-profiles use work once in a repo. It writes a one-line .claude-profile, and a shell hook picks the account every time you enter that tree.

  • Plain claude just works: no prefix to remember
  • Pure-shell lookup, so directories without the file start no processes
  • zsh, bash and PowerShell, with a prompt indicator for starship and oh-my-posh
~/code/agency-saas/.claude-profile 
work

~/code/side-project $ cd ../agency-saas
(work) ~/code/agency-saas $ claude
  # CLAUDE_CONFIG_DIR=~/.claude-work

(work) ~/code/agency-saas $ cd ~/code/side-project
~/code/side-project $  # primary again, automatically

Two desktop apps, side by side

Each profile launches the Claude desktop app against its own data directory, with its own login, MCP servers and window state. Add a clickable launcher to the Dock, Start menu or app grid.

  • Per-profile MCP config, so two instances never fight over a port
  • Handles Windows MSIX / Store installs, which reject launch arguments
  • Your primary ~/.claude is never touched

A doctor for when Claude updates

This drives documented variables, not a supported API, so an update can move things. claude-profiles doctor answers "what changed?" in one command, with --json for CI.

  • Finds credentials that silently outrank a profile, like a stray ANTHROPIC_API_KEY
  • Flags MCP port collisions between profiles before you hit them
  • Reads Keychain metadata only. It never prints or prompts for a secret

Safety

Written for a tool that touches your credentials.

You can read every line it runs. That is why it is bash and PowerShell, not a compiled binary.

Cloned repos are treated as hostile

A .claude-profile can only name a profile you already registered. It cannot create one, point at a directory, pass a flag or trigger a login. Unknown names warn and leave you on your primary account; they never fall through to a different one.

Nothing edits your shell

The installer prints the one line to add. You paste it.

Secrets stay put

Keychain, DPAPI or libsecret. Health checks read metadata only.

Owner-only files

Registry mode 600, state 700. ACLs stripped to you on Windows.

Deletes ask first

Every destructive prompt answers no on a closed stdin, so CI never removes data.

What it will not do

Two accounts for two jobs is ordinary. Rotating accounts to dodge limits is not.

Some account switchers fail over to another account when you hit a rate limit. That is the kind of behaviour Anthropic's usage policy covers, and it puts every account involved at risk.

claude-profiles has no scheduling, no automatic failover and no way to switch on a rate-limit error. It exists for separate contexts: a personal account and an employer's, or two clients who should never share history.

Get started

Three commands. About two minutes.

Install

Latest release into ~/.claude-profiles, linked into ~/.local/bin.

curl -fsSL https://raw.githubusercontent.com/inevitable-lettus/claude-profiles/main/install.sh | sh

Hook your shell

Add one line to ~/.zshrc, ~/.bashrc or your PowerShell profile.

eval "$(claude-profiles shell-init zsh)"

Add a profile, log in

Your existing login stays your primary account.

claude-profiles init
claude-profiles add work
claude-profiles run work -- /login
# then, in a repo:
claude-profiles use work
